# Как соединены Codex и EffectCraft

Этот проект добавляет локальный HTTP API и удобный запуск **официального MCP EffectCraft 0.13.0**. Команды редактирования, свойства, эффекты, история и рендеринг исполняются самим EffectCraft. Здесь нет отдельного движка, эмуляции интерфейса или конечной точки `/prompt`: текстовый запрос понимает модель Codex, после чего вызывает инструменты программы.

## Два независимых входа

```text
Пользователь → Codex → MCP / stdio → официальный effectcraft-cli
                                      ├─ live: TCP 127.0.0.1:9877 → окно EffectCraft
                                      └─ headless: отдельный движок без окна

Локальный Python-клиент → HTTP 127.0.0.1:8767 + Bearer token
                       → этот API → TCP 127.0.0.1:9877 → окно EffectCraft
```

**MCP не проходит через HTTP API.** Для MCP используется нативный сервер `effectcraft-cli mcp`: его каталог и схемы остаются источником истины. При проверке версии 0.13.0 сервер перечислил 27 инструментов headless и 36 live. Если версия изменилась, нужно заново вызвать `tools/list`, а не полагаться на эти числа.

HTTP API нужен собственным скриптам и другим локальным клиентам. Он переводит аутентифицированные HTTP-запросы в официальный JSON-lines control protocol. `/v1/rpc` принимает **метод control protocol**, например `ui.inspect`; `/v1/command` принимает **команду движка**, например `comp.new`. Эти пространства имён различаются.

## Live и headless

Live соединяется с конкретным экземпляром приложения, запущенным с `--control 9877`. Все изменения видны в его проекте. Если окно открыто без control channel, регистрация MCP не включает его задним числом: сохраните работу и отдельно запустите приложение с этим флагом. Обёртка не должна завершать чужую сессию или автоматически заменять её проект.

Headless создаёт отдельную сессию без окна. Это полезно для пакетной генерации и CI, но не управляет существующим окном пользователя. Обёртка включает нативный `--autosave` для headless. Укажите `--project` для явно выбранного файла и сохраняйте результаты в выбранное место до выхода: checkpoints предназначены для восстановления и не заменяют явную передачу результата.

Переход из live в headless после ошибки **не выполняется**: иначе результат мог бы оказаться в другой сессии незаметно для пользователя.

## Последовательность нормальной работы агента

1. Прочитать `get_state`, `get_project` и активную композицию.
2. Найти команду через `list_commands` и получить её схему через `describe_command`.
3. Выполнить минимальное изменение; использовать возвращённые id объектов.
4. Проверить свойства и получить `render_frame` / `render_preview`.
5. При необходимости сделать следующий проход и сохранить проект в явно выбранный файл.

Для live полезны `ui_inspect`, `ui_elements` и `screenshot`. Координаты из `ui.elements` заданы в логических точках окна; координаты слоя или композиции могут быть в пикселях. Вызов `ui.focus` захватывает фокус, поэтому его стоит применять только когда он действительно нужен.

После регистрации сервера через `codex mcp add` уже открытый чат может ещё не видеть его инструменты. Перезапустите MCP-подключение/чат или Codex и проверьте список инструментов. Успешная запись конфигурации не доказывает, что инструменты доступны в текущем ответе.

## Форматы и ошибки

Нативный MCP использует JSON-RPC 2.0 через stdin/stdout, по одному JSON-объекту на строку. API-обёртка не пишет диагностические сообщения в stdout этого процесса. Нативный control channel — другой протокол: `{id, method, params}` и ответ `{id, ok, result}` либо `{id, ok:false, error}` поверх TCP.

HTTP API возвращает одну из двух оболочек:

```json
{"ok":true,"result":{"example":"native result, unchanged"}}
```

```json
{"ok":false,"error":{"code":"example","message":"Описание ошибки","outcome_unknown":false}}
```

Состав полей внутри `result` определяет EffectCraft. Вложенный результат `script.run` или пакетной команды может сам сообщать об ошибке: HTTP 200 не заменяет проверку доменного результата. Аналогично в MCP нужно проверять `isError`, `failed` и результаты отдельных шагов.

Один API-клиент сериализует обращения к control channel. Это сохраняет порядок запросов внутри процесса API, но не блокирует действия пользователя и другие MCP/CLI-клиенты. На время критичной серии изменений лучше не редактировать тот же проект параллельно.

Сетевой тайм-аут после отправки команды не доказывает, что команда не исполнилась. Ответ с `outcome_unknown:true` требует осмотра состояния до повторения. HTTP-обёртка не повторяет запрос автоматически. Нативный MCP имеет собственное ограниченное повторение явно безопасных чтений; обёртка не добавляет повторений поверх него.
