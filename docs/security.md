# Безопасность и сохранность проекта

## Граница доверия

API привязан к `127.0.0.1`, требует Bearer token и рассчитан на доверенные локальные клиенты. Он не предназначен для публикации в интернете, локальной сети, туннеле или публичном reverse proxy. Нативный control channel EffectCraft тоже слушает только loopback, но **не имеет аутентификации**. HTTP-токен защищает вход через эту обёртку, а не закрывает прямой доступ других локальных процессов к control channel.

Владелец токена может выполнять команды EffectCraft, включая сохранение/открытие файлов и запуск сценариев в пределах прав приложения и его настроек. Обёртка **не является файловой песочницей**. Безопасность нельзя свести к отсутствию произвольного чтения файлов через HTTP GET: команды движка тоже обладают полномочиями.

## Что делает HTTP-сервер

- Проверяет Bearer token для всех маршрутов, включая health и OpenAPI.
- Проверяет `Host`, запрещает запросы с `Origin`, не включает CORS и не обслуживает браузерный фронтенд.
- Принимает JSON с ограниченным размером и корректной структурой; отвергает неизвестные поля и неподходящие типы.
- Не принимает `Transfer-Encoding`; не обслуживает произвольные файлы и не запускает shell по HTTP.
- Возвращает кадр PNG в base64 без файлового пути в запросе `/v1/render-frame`.
- Не пишет токен, авторизацию и параметры команд в журнал запросов.
- Не повторяет команду автоматически после сетевой ошибки.

Эти меры уменьшают случайный доступ и атаки из браузера, но не защищают от вредоносной программы с правами того же пользователя. Не передавайте токен в URL, не коммитьте runtime-каталог, не вставляйте его в сообщения или опубликованные примеры. Чтение токена из защищённого файла, как в `examples/api_client.py`, помогает не хранить его в истории терминала.

Runtime-файлы по умолчанию находятся в игнорируемом Git каталоге `.state` рядом с обёрткой; расположение можно изменить через `--state-dir`. Токен `.state/api-token` хранится с правами `0600`; каталог должен быть доступен только владельцу. Чтобы прекратить доступ, остановите API и MCP/управляемую сессию, когда они больше не нужны. Для отзыва уже выданного токена остановите API и замените token-файл новым значением перед новым запуском. Удаление токена при работающем процессе само по себе не отзывает его из памяти.

## Нативная изоляция файлов MCP

Официальный CLI поддерживает повторяемые `--automation-read-root DIR` и `--automation-write-root DIR`. Они проверяют файловые параметры команд, разрешают чтение в read/write roots и запись только в write roots. В этом режиме upstream отказывает в сценариях и некоторых путях обхода, включая произвольный `control` и инструменты управления UI. Это существенный компромисс: полный live-доступ и строгая файловая изоляция не равнозначны.

Для ограниченного MCP запускайте официальный CLI с этими флагами напрямую или добавляйте их к его args после проверки справки версии 0.13.0. Пример конфигурации дан в `examples/mcp-config.example.toml`. Ограничения MCP не превращают отдельный HTTP API или незащищённый нативный порт в ту же песочницу.

## Работа с текущим документом

Перед изменениями агент читает состояние. Перед заменой текущего документа нужно явно сохранить работу. Нативные `open_project`, `file.open`, `file.newProject`, `file.closeProject` и `file.revert` могут обойти диалог сохранения. Не используйте их как автоматическую «подготовку» соединения.

Не завершайте существующее приложение с `app.quit {"force":true}`. Флаг принудительного выхода пропускает запрос сохранения. Не делайте автоматический перезапуск приложения для включения control channel, пока текущая работа не сохранена.

Сценарий `examples/demo.jsx` добавляет отдельную композицию к текущему проекту, не открывает и не очищает документ и не сохраняет его поверх существующего файла. Изменения объединены в undo group. Сценарий может частично исполниться до исключения: undo group делает отмену удобной, но не превращает script.run в транзакцию с откатом. Для атомарной серии команд рассмотрите нативный `batch` и проверяйте результат.

## Неопределённый результат

Если ответ потерялся, команда могла уже изменить проект. При `outcome_unknown:true` сначала прочитайте состояние, композицию/слои, историю и целевой файл. Только после проверки явно решайте, нужен ли повтор. Особенно опасно слепо повторять создание слоёв, импорт, сохранение, запись рендера и применение эффектов.

## Публикация кода

В репозиторий входят исходники, тесты, примеры и документация. Бинарники EffectCraft, локальные пользовательские проекты, токены, MCP-конфигурация с личными путями, журналы и runtime-state не должны попадать в коммит. Проверяйте подготовленный diff перед публикацией; наличие `.gitignore` не удаляет секреты, которые уже отслеживаются Git.
